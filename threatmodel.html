Cyber threat modelling

Upload an architecture or network diagram. This page breaks it into elements, data flows and trust zones (CSA Guide to Cyber Threat Modelling §3.2), walks every element through STRIDE-LM using the threat profile from the Threat Profile tab (§3.3), and maps each threat to MITRE ATT&CK — and, for AI elements, to MAESTRO and MITRE ATLAS. You get two downloads: the threat register and the data-flow diagram with its threats.

  2. 2 Architecture diagram

    Use a draw.io diagram (File > Export as > XML, or the .drawio file) or a PowerPoint slide drawn with shapes and connectors: the page reads the elements, data flows and trust zones from them. A picture of a diagram has none of that to read, so you either decompose it by hand below or, where the server allows it, have Claude read it.

  3. 3 System decomposition

    Check what was read, and fill in each element's context: what it does, the data it holds, how it authenticates and how far it is trusted. This decides the threats and their severity more than anything else — "Restricted — PII" and "Internal" produce very different registers.

    DFD check

    Following the DFD method, it puts each element in the trust zone its position is drawn in and redraws the layout in CSA notation: always for a picture Claude read, and for any other diagram unless the redrawn layout would have more problems with where things are drawn (overlaps, elements across a zone’s border) than the diagram has. Then it checks that every element is joined by data flows and drawn in a trust zone. It never adds a data flow, or puts an element in a zone, that the diagram doesn’t show.

  4. 4 Threat model and deliverables

    Every element is walked against all seven STRIDE-LM categories, through the profile's threat themes. Each threat event cites MITRE ATT&CK techniques — ◆ where MITRE records the profile using them — with their mitigations and detection strategies. It is a rigorous first pass for an analyst to review, not a finished assessment.
